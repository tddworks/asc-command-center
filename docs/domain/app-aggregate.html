Aggregate · App

The root of the App Catalog context. Documents what src/app/ actually implements — rich domain with affordance-gated navigation via the AppRepository port.

The shape

App is the root. Two value objects live inside its consistency boundary: Affordances (the server's capability map) and ContentRights (an optional declaration). Everything else — Version, Build, AppInfo, Screenshot — is referenced by ID and reached via the repository, never embedded.

Why affordances-as-VO

Affordances is the load-bearing design choice. The server decides what's allowed next; the aggregate translates those strings into typed capability getters (canViewBuilds, canViewVersions). Client code never inspects keys — it asks the aggregate. Change the server's HAL shape and only normalizeLinks needs to move.

Rich vs. pure

An App constructed without a repo is a pure value object — useful for tests, for fixtures, for hydrating from mocks. An App constructed with a repo can traverse to other aggregates. withRepository() lifts a pure App into a navigable one. This is why the field is private readonly repo?, not a mandatory constructor argument.
